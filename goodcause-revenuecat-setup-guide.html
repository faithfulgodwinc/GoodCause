GoodCause — RevenueCat Production Setup

Full walkthrough: Google Play Console → Google Cloud → RevenueCat dashboard → Expo/React Native code config

Updated: Google Play Console has removed the old "API access" menu. You no longer link a Google Cloud project to Play Console. Instead, you create a Service Account in Google Cloud first, then add it directly as a user in Play Console. Steps 1.3–1.5 below reflect this new flow.
What you're building: A monthly "commitment" subscription where the user picks how much they want to give (₦1,000 / ₦2,500 / ₦5,000 / ₦10,000 per month). Each tier is a separate in-app subscription product. RevenueCat manages entitlement, receipt validation, and cross-platform state. Your app already has the sandbox packages and paywall UI — this guide wires it all up to real billing.

1 Google Play Console — Subscriptions & Service Account

1.1 — Prerequisites

  • Your app must be uploaded to Play Console at least once (even as an internal test track) before you can create in-app products.
  • App package: com.goodcause.app
  • Your developer account must have a Google Payments merchant account linked.

1.2 — Create the Subscription Products

1
Go to Play Console → Your App → Monetise → Products → Subscriptions
2
Click "Create subscription"
3
Create all four products using these exact product IDs:

  • Subscription ID: the product ID from the table above
  • Name: shown in Play Store billing dialog
  • Base plan: click "Add base plan" → set billing period = Monthly, set price in NGN
  • Grace period: 7 days (recommended)
  • Leave trial period empty unless you want a free trial
5
Click Activate on each base plan. Products must be active before RevenueCat can sync them.

1.3 — Create a Google Cloud Service Account

New flow: There is no longer an "API access" menu in Play Console. You create the service account in Google Cloud first, then invite it into Play Console as a user.
1
Go to console.cloud.google.com → create a new project (e.g. GoodCause) or use an existing one
2
Navigate to IAM & Admin → Service Accounts → + Create Service Account
3
Name it something like goodcause-play-revenuecat → click Create and continue
4
For the role, select Service Account User → click Continue → Done
5
Open the service account you just created → go to the Keys tab → Add Key → Create new key → JSON → download the .json file. Keep this file secret.
6
Note the service account's email address — it looks like goodcause-play-revenuecat@your-project.iam.gserviceaccount.com. You'll need it in the next step.

1.4 — Enable the Google Play Android Developer API

1
In Google Cloud Console → APIs & Services → Library
2
Search for "Google Play Android Developer API" → click it → click Enable

1.5 — Grant the Service Account Access in Play Console

1
Go to Play Console → Users and permissions → Invite new users
2
Paste the service account email address from step 1.3.6 into the email field
3
Under Account permissions, grant: View app information and View financial data, orders, and cancellation survey responses
4
Under App permissions, also add com.goodcause.app and grant it the same financial data permissions at the app level
5
Click Invite user (ignore the "no email will be sent" notice — service accounts don't receive emails)
Wait 24–48 hours after granting access before connecting to RevenueCat. Google's permission propagation can take time and RevenueCat will fail to verify the credentials if you connect too soon.

3 Add API Keys to Your Expo Environment

3.1 — Create / update frontend/.env

# RevenueCat — from dashboard Project Settings → API Keys EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY=goog_xxxxxxxxxxxxxxxxxxxxxxxxxxxx EXPO_PUBLIC_REVENUECAT_IOS_API_KEY=appl_xxxxxxxxxxxxxxxxxxxxxxxxxxxx # Only needed if you want a single test key during development # EXPO_PUBLIC_REVENUECAT_TEST_API_KEY=rcb_test_xxxxxxxxxx # Your backend URL EXPO_PUBLIC_BACKEND_URL=https://your-backend.com
Never commit .env to git. Confirm .env is in your frontend/.gitignore. For EAS Build, add these as EAS Secrets instead (see step 3.2).

3.2 — Add to EAS Build Secrets (for production builds)

eas secret:create --scope project --name EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY --value "goog_xxx" eas secret:create --scope project --name EXPO_PUBLIC_REVENUECAT_IOS_API_KEY --value "appl_xxx"

Run these from the frontend/ directory. EAS will inject them at build time automatically.

4 Code Changes in revenuecat.tsx

4.1 — What already works ✅

  • initializeRevenueCat() reads EXPO_PUBLIC_REVENUECAT_ANDROID_API_KEY / EXPO_PUBLIC_REVENUECAT_IOS_API_KEY automatically
  • Falls back to SANDBOX_PACKAGES when no live key is present
  • useSubscription() → availablePackages returns live packages when keys are set, sandbox otherwise
  • Paywall reads availablePackages and renders each tier
  • Entitlement identifier is already "pro"

4.2 — One required change: add the RevenueCat plugin to app.json

The react-native-purchases SDK requires a native plugin entry to work properly in production builds:

// In frontend/app.json — add to the "plugins" array: "plugins": [ "expo-router", "react-native-purchases", // ← add this line ... ]

4.3 — Verify package identifiers match your RevenueCat offering

In revenuecat.tsx, your sandbox packages use identifiers tier_1k, tier_2k5, tier_5k, tier_10k. These are the package identifiers you created in the RevenueCat offering. The live availablePackages from RevenueCat will also carry these identifiers — the paywall UI will render them identically.

4.4 — How purchase flow works end-to-end

  1. User opens Paywall → selects a tier (e.g. ₦5,000/month)
  2. purchase(pkg) is called → RevenueCat triggers the Play Store billing sheet
  3. User completes payment on Play Store
  4. RevenueCat validates the receipt server-side with Google using the service account credentials
  5. customerInfo.entitlements.active["pro"] becomes truthy
  6. isSubscribed → true — Pro features unlock instantly

7 Important Notes

Subscription vs. Donation distinction

The monthly commitment tier is the user's GoodCause Pro subscription — it unlocks features (AI assistant, analytics, etc.). It is NOT directly the donation amount sent to campaigns. Actual campaign donations are separate one-off transactions via Paystack. Make sure your Play Store listing description reflects that this is a platform subscription fee, not a direct charity donation — Google may reject apps that obscure this.

Nigeria / NGN on Google Play

Google Play supports NGN as a billing currency. Set prices in NGN directly in the Play Console base plan pricing section. Do not use USD and convert — set NGN natively so the user sees ₦ on the billing sheet.

RevenueCat free tier

RevenueCat's free plan covers up to $2,500 MTR (monthly tracked revenue). GoodCause will comfortably fit within this for a long time. No payment required to get started.

Web platform

RevenueCat does not support web billing. Your code already handles this: rcEnabled = Platform.OS !== "web". On web, the sandbox simulation is used. If you need web subscriptions in the future, integrate Stripe separately.

Service account permission propagation

After granting Play Console access to the service account, wait 24–48 hours before testing RevenueCat's connection to Google Play. Attempting to connect too early will result in a "credentials invalid" error even though the setup is correct.
